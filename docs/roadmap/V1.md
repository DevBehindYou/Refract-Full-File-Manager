# V1 Scope

Everything here assumes the MVP is stable in the field. V1 adds depth to what exists rather
than new pillars.

## 1. Themes of V1

1. **Cleanup that users trust** — duplicates, empty folders, smarter large-file tools.
2. **Power-user speed** — drag and drop, range selection, keyboard support, bookmarks.
3. **Format depth** — more archive formats, better document viewing, text editing.
4. **Large-screen maturity** — three-pane, drag between panes, proper keyboard navigation.
5. **The module split** — see §5.

## 2. Features

**Duplicate finder.** Two-stage: group by size, then hash only within groups — never hash the
whole device. Content-identical only; no "similar image" fuzziness, which produces false
positives that cost photos. The UI **never pre-selects every copy in a group**, always keeps
one selected-to-keep by default (oldest, or the one in a non-cache location), and shows where
each copy lives before deletion.

**Empty-folder cleanup.** Recursive detection, preview before delete, excludes folders that
contain only hidden files unless the user opts in.

**Drag and drop.** Within a folder onto a subfolder, and between panes on large screens.
Requires a long-press-to-lift affordance, a clear drop target, and an undo — a mis-drop is a
move the user did not intend.

**Range selection.** Long press and drag to select a run; shift-click equivalent on keyboard.

**Text editing.** Save is the dangerous part: write to a temp file in the same directory, fsync,
then atomically rename over the original. Never truncate-and-write in place. Size-capped, with
an explicit "this file is too large to edit safely" state.

**Archive depth.** 7z and RAR extraction (read-only), encrypted-ZIP password prompt, per-entry
extraction, archive creation with compression level choice.

**PDF depth.** Text selection, in-document search, page thumbnails, rotate.

**Bookmarks and custom quick access.** User-defined Home shortcuts, reorderable.

**Three-pane large screen.** Persistent folder tree, list, detail. Drag between the tree and
the list. Full keyboard navigation with a documented shortcut map.

**Widgets and quick settings.** Storage-status widget; a quick-settings tile for the storage
scan.

**Sort and filter memory.** Per-folder sort preference, remembered.

**Batch rename.** Pattern-based, with a live preview of every resulting name before applying,
and a conflict check up front. Batch rename without a preview is a data-destruction tool.

## 3. Network storage (V1 or V1.1, gated)

FTP / SFTP / SMB is the only V1 item that changes the app's security posture, because it
introduces the `INTERNET` permission and remote credentials. Conditions before it ships:

* It lives in a separate flavour, so the local-only build remains network-free.
* Credentials are stored in `EncryptedSharedPreferences` or the Keystore, never in plain
  DataStore.
* The privacy policy and store listing are updated *before* the feature is visible.
* Remote errors get their own `FileError` branches; network timeouts must never be reported as
  "file not found".

If any condition is not met, it slips. This one is not worth shipping early.

## 4. Quality work in V1

* Baseline Profile regeneration for the new journeys.
* Room migration test coverage for every V1 schema change.
* A performance regression suite in CI, not just nightly.
* Localisation: the top languages by install base, with RTL layout verified.
* An accessibility audit by someone who uses a screen reader daily, not by the team.

## 5. The module split

The MVP is one Gradle module with boundaries enforced by Lint. V1 splits it — **when at least
two of these triggers are true**, not on a schedule:

| Trigger | Threshold |
|---|---|
| Clean build time | > 2 minutes |
| Incremental build after a UI change | > 30 seconds |
| Contributors working in parallel | > 2 |
| Lint suppressions on boundary rules | > 5 accumulated |
| A second app target (Wear, TV, a demo) | Exists |

**Target split when it happens:**

```text
:app
:core:model        :core:common      :core:designsystem   :core:ui
:core:data         :core:database    :core:datastore
:feature:browse    :feature:search   :feature:preview
:feature:storage   :feature:operations  :feature:settings
:glass
```

`:glass` is deliberately a leaf that nothing depends on except `:core:ui` — which is what makes
it deletable. The split is mechanical if the Lint rules have been doing their job; if it turns
out to be hard, that is evidence the rules were being suppressed.

## 6. Still out of scope in V1

Cloud sync, root access, document editing engines, media library management, "AI" features that
require a network round trip, and anything that would put the app's local-first promise at risk.
